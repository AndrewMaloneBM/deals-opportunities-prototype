## Why it matters?
In scope: Always-on Deals, active campaigns and existing seller listings.
Out of scope: sourcing opportunities, exclusive Deals and other seller incentives.

## What does success look like?

| Metric | Definition | Baseline | Target |
|---|---|---|---|
| Deal adoption rate | GMV at Deal target price ÷ total GMV generated by products in the Deal scope | 35–40% | 50–60% |
| Seller participation | Sellers with Deal GMV > 0 / sellers in the deal scope | 79.4% in July–Aug | — |
| Assess → Act | Sellers opening Deal details and taking an action (update price / create listing / status moving from Above target or Near target to In Deal) | Not tracked today | To define |

### What's the plan? (full roadmap, this project is Step 0 + Step 1 only)
- **Step 0**: Bring Deal information into the seller's existing listing export (ASSESS)
- **Step 1**: Create a Deals tab connected to Listings and show listing-level eligibility statuses (DISCOVER + ASSESS + ACT)
- **Step 2**: Add financial context to help sellers assess whether action is worthwhile (ASSESS)
- **Step 3**: Improve discovery through homepage entry points and measure seller actions and Deal business impact (DISCOVER)
- **Step 4**: Add "ended" campaign information so sellers can track performance of former Deals campaigns (TRACK)

## User Stories

### Access / Entry point
- As a seller, I want to access the Deals Opportunities page from the Listings page, so that I can move from my listings to relevant active Deals.
- As a seller, I want to see active Deals campaigns in the new Deals tab in Opportunities page, so that I can discover active Always-on Deals.

**Acceptance:**
- The Listings page includes the agreed Deals entry point.
- Clicking it opens the Deals tab in Opportunities.
- **The entry point is only displayed when there is an active and relevant Deal, if relevance data is available.**
- The tab follows the existing Opportunities navigation pattern.
- The route is accessible through `/opportunities/deals`.

### Campaign details
- As a seller, I want to see all active Always-on Deal campaigns, so that I can identify which campaigns may apply to my stock.
- As a seller, I want to paginate through active Deal campaigns, so that I can navigate the list even when many campaigns are available.
- As a seller, I want to open an active Deal campaign, so that I can understand which of my products and listings are affected.
- As a seller, I want to see the products and listings covered by a Deal campaign, so that I can understand which items require action.

**Acceptance:**
- Each campaign card should display: campaign name; campaign status; start date; end date; covered markets; number of models.
- **Only active/validated campaigns are displayed in the MVP.**
- Clicking a campaign card opens a drawer with campaign name, dates, status, markets (+ the listings/models table, per "Listings statuses" below).

### Listings statuses
- As a seller, I want to understand whether each listing is already in the Deal or needs action, so that I know what to do next.

| User-facing status | Backend value | Definition |
|---|---|---|
| In Deal | `IN_TARGET` | Listing price is equal to or below the Deal target price |
| Near target | `NEAR_TARGET` | Listing price is above target but no more than 3% above it |
| Above target | `FAR_TARGET` | Listing price is more than 3% above the target price |
| Not listed | `NOT_LISTED` | No active listing exists for the seller, product and relevant special-offer configuration |

### Actions
- As a seller, I want to open an existing listing from the Deal drawer, so that I can review or manage it.
- As a seller, I want to update the price of a listing that is near or above the Deal target, so that I can decide whether to qualify for the Deal.
- As a seller, I want to create a listing for an eligible product that is not currently listed, so that I can participate when I already hold the relevant stock.

**Acceptance:**
- `In Deal` listings expose a **See listing** action ⇒ it opens the relevant listing. *(Note: the PRD's own Tracking strategy section, below, calls this same action **"View listing"** — an internal inconsistency in the source doc. Per Andrew's decision, this prototype follows front-apps' actual shipped code, which uses "View listing".)*
- `Near target` and `Above target` listings expose an **Update price** action ⇒ it opens the correct listing context.
- **Create listing is only shown when the product is eligible** (i.e. `Not listed` alone isn't sufficient — the product must also be in-scope/eligible for the campaign).

### Filtering
- As a seller, I want to filter campaign listings by status, market and product type, so that I can find the listings requiring action without navigating thousands of rows.
- Open question in the PRD: "check with Data team if we can split campaigns" — not applicable to this mocked prototype.

## Dependencies
Data team.

## Risk
- Campaigns can contain a LOT of models, and filtering large datasets may take more than 30 seconds with the current data source.
- Large campaigns may need to be split into smaller single-category campaigns.
- **Not applicable to this prototype** — our fixture set is intentionally small and deterministic; we simulate a *credible pagination state* per the brief without needing to reproduce this real performance risk.

## Rollout plan
1. Enable the feature for internal testing.
2. Roll out to a small seller cohort, starting with ASA sellers.
3. Expand before the Back Forum if data quality and performance are acceptable.

## Tracking strategy
TBC in the real product, but the following event list is given and is the strongest available source for this prototype's event-logging taxonomy (see `../../PLAN.md` §19):
